# NetSee 威胁模型

## 资产与信任边界

| 信任区域 | 内容 | 边界 |
|---|---|---|
| 客户端主机 | 本地网络事实、出网环境、报告 | 报告本地生成不上传；用户自持 |
| 公网 | 客户端 ⇄ 探针路径 | 中间节点可观测（这正是被测对象），不可信 |
| 探针 VPS | 会话注册表、观测记录 | 公开可达，属于攻击面；无敏感持久化 |

信任原则：探针是测量仪器，不是信任锚点；任何人可向探针发起任意流量。探针的安全目标不是"防窥探"，而是**不可利用性**：不执行载荷、不持久化、不泄露其他会话。

## 威胁与控制

| ID | 威胁 | 控制 |
|---|---|---|
| THR-PROBE-001 | 恶意客户端向探针注入畸形/超长载荷 | CTL-PROBE-001：固定 schema 解析、长度上限、畸形拒绝；fuzz 冒烟（ACC-P5-001） |
| THR-PROBE-002 | 枚举会话 ID 拉取他人观测 | CTL-PROBE-002：UUID v4、未知/过期 404、TTL 清理（ACC-P1-006/007） |
| THR-PROBE-003 | 探针被攻破后作为跳板/数据源 | CTL-PROBE-003：最小监听面、无执行载荷、零落盘、无长期凭证（ACC-P5-003/004） |
| THR-PROBE-004 | 资源耗尽（并发/内存） | CTL-PROBE-004：并发上限、注册表内存上限、读写超时 |
| THR-CLIENT-001 | 报告泄露出网环境敏感信息 | CTL-REPORT-001：本地生成不上传；报告明确标注暴露面语义（ACC-P3-001） |
| THR-CLIENT-002 | DNS 劫持环境下测量结果误导 | CTL-CLIENT-001：DoH 对照 + fake-ip 抑制 + 归因（ACC-P2-004） |
| THR-CLIENT-003 | TUN 代理下把代理出口当本机直连 | CTL-CLIENT-002：路径归因层必须启用（ACC-P2-005/008） |
| THR-NET-001 | ISP 对探针端口入站过滤导致误判 | CTL-PROBE-005：多端口自发现 + 客户端比对探针回报（ACC-P2-006） |

## 拒绝路径要求

- 探针：畸形 JSON、超长 header、超大 UDP 载荷、并发洪泛——拒绝且不崩溃、不记录完整载荷。
- 客户端：探针不可达、无公网、权限不足——明确失败信息，不产生误导性报告。

## 已知边界

- 单 IP 探针 NAT 分类不完整（全锥 vs 受限锥、对称 vs 端口依赖映射需第二 IP）——报告显式标注前提。
- 指纹保质期短（JA3 随 uTLS/浏览器更新失效）——对比优先于绝对值。
- 探针不承担正式 PKI；TLS 证书内存自签，仅用于指纹嗅探。
